# 코딩 행동 원칙 (Karpathy Guidelines)

## 1. 코딩 전에 먼저 생각하라
- 가정이 있으면 명시적으로 밝히고, 불확실하면 물어봐라
- 해석이 여러 가지라면 선택지를 제시하고, 조용히 하나만 고르지 마라
- 더 단순한 접근법이 있다면 말해라
- 혼란스러운 부분이 있으면 멈추고 무엇이 불분명한지 밝혀라

Place 예시: bounds 쿼리 로직 구현 전, 줌 레벨 분기 전략 가정을 먼저 명시하고 확인받아라.

## 2. 단순함이 우선이다
- 요청받지 않은 기능을 추가하지 마라
- 단일 사용 코드에 추상화를 만들지 마라
- 200줄로 쓸 수 있는 걸 50줄로 쓸 수 있다면 다시 써라

Place 예시: 마커 컴포넌트 구현 시 미래의 모든 소스를 고려한 범용 시스템을 선제적으로 설계하지 마라.

## 3. 외과적 변경만 하라
- 요청과 무관한 코드, 주석, 포매팅을 건드리지 마라
- 멀쩡한 코드를 리팩터링하지 마라
- 기존 스타일을 그대로 따라라
- 관련 없는 데드 코드는 삭제 말고 언급만 해라
- 모든 변경된 줄은 요청 사항으로 직접 추적 가능해야 한다

Place 예시: FilterBar 수정 요청 시 MapContainer 로직을 함께 "개선"하지 마라.

## 4. 목표 기반으로 실행하라
작업을 검증 가능한 목표로 전환하라:
```
1. [단계] → 검증: [확인 방법]
2. [단계] → 검증: [확인 방법]
```

Place 예시:
```
1. bounds 기반 쿼리 함수 구현 → 검증: 지도 이동 시 네트워크 탭 요청 확인
2. 클러스터 마커 렌더링    → 검증: 줌 10 이하에서 개별 마커 미표시 확인
3. 필터 상태 연동          → 검증: 유튜브 필터 ON 시 유튜버 마커만 표시 확인
```

## 절대 금지
- 16만 건 전체를 한 번에 렌더링하지 않는다 (bounds 기반 쿼리 필수)
- CustomOverlayMap은 줌 14 이상에서만 사용
- Gemini 768-dim pgvector 기존 데이터 재생성 없이 그대로 사용
- 요청하지 않은 기능 선제 구현 금지
- 작업 범위 외 코드 수정 금지
