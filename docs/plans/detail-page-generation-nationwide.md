# 상세페이지 생성 로직 완성 + 전국 확장 구현계획

_2026-07-18 · 지금까지 수집·감사·재시딩에서 배운 것을 종합_

## 목표
**"상세페이지 하나를 완전하고 정직하게 생성하는 로직"을 완성**한 뒤, 그것을 지역 파라미터만 바꿔 **전국 단위로 반복 실행**한다. 지금은 유튜브 단일 소스라 상세페이지가 반쪽(전화·영업시간·주차·큐레이션·임베딩 결손)이므로, 다중 소스를 하나의 결정적 파이프라인으로 합치는 것이 핵심.

## 배운 것 요약 (이 계획의 근거)
- 재시딩이 유튜브 단일 소스라 **전화 0/49·주차 0/49·영업시간 대부분 결손·임베딩 0·큐레이션 0**. 기존 `data_pipeline`의 TourAPI/착한가격/임베딩 로직이 빠짐.
- 유튜브 멀티모달은 **근거 강제로 환각 0**, review/장면/가격근거까지 고품질. 단 "대표=조회수 1등" 버그와 "미식 리뷰성 미판정"(코미디·ASMR 통과) 한계.
- 상세페이지에 **가짜 요소**(하드코딩 별점·mock 밀키트 할인·허위 미쉐린 문구)가 신뢰를 훼손. → 정직화 필요.
- **PC 버전(RestaurantInfoCard) 우선.** 모바일은 그다음.

## 1. 상세페이지 데이터 모델 (완전한 카드가 필요로 하는 것 · 소스)

| 블록 | 필드 | 1차 소스 | 폴백 |
|------|------|---------|------|
| 신원/위치 | name·category·address·lat/lng·kakao_place_id·**phone** | Kakao 로컬 | — |
| 영업/편의 | business_hours·parking·packaging·reservation | **관광공사 TourAPI**(opentimefood 등) | 영상 멀티모달 / 구글검색 그라운딩 |
| 메뉴 | menu_info | TourAPI 대표메뉴 + 영상 picks | Kakao |
| 리뷰(핵심 차별점) | quote·review·picks(가격+근거+코멘트)·tips·signature·mood_tags·best_food_scenes | **YouTube 멀티모달** | — |
| 권위/큐레이션 | content_tags(미쉐린/블루리본/또간집/착한가격) | curation 스크립트 → restaurant_curations | — |
| 검색 | embedding | 임베딩 생성 | — |
| 대표영상 | representative_video_id | 리뷰적합도 선택(신규) | 최다조회 |

**정직성 원칙:** 위 소스로 채우지 못한 필드는 **비워두고 정직하게 표시**(빈 상태 + 제보 유도). 별점·할인·인증을 **지어내지 않는다.**

## 2. 통합 per-restaurant 파이프라인 = "상세페이지 생성기"

하나의 식당(seed 신원)을 받아 결정적 순서로 완전한 레코드를 만든다. 각 단계 **멱등(idempotent)** — 재실행 안전, 이미 채워진 건 스킵.

```
generateDetail(seed):
  1. resolveKakao      → place_id, 정규 name/category(음식점 게이트), coords, phone     [필수]
  2. enrichFacilities  → TourAPI(name+지역) → hours/parking/packaging/reservation/menu   [결손 보완]
  3. enrichReviews     → YouTube 후보검색 → 리뷰적합도 랭킹 → 멀티모달 게이트 →
                         ai_insights(근거강제) · representative_video 지정 · 다중영상 폴백  [핵심]
  4. enrichCuration    → 착한가격/미쉐린/블루리본/또간집 매칭 → content_tags               [권위]
  5. enrichEmbedding   → 합성 컨텍스트 → 임베딩                                          [검색]
  6. publishGate       → 완성도·리뷰신뢰도 기준 is_published 결정                         [품질]
```

## 3. 발견(Discovery) 레이어 — 전국 대상 확보 [결정: 리뷰 우선만]

**"유튜버 리뷰가 있는 곳만" 등록** (차별점 집중, 결정됨). 관광공사·착한가격은 **발견이 아니라 보강(2단계)·큐레이션(4단계) 소스로만** 사용.
- **YouTube 발견** — 지역별 음식 쿼리, 조회수순, 음식점 게이트 + **채널/콘텐츠 게이트(§4-1·4-2)**. 현 seed_gwangju를 **지역 파라미터화**. 즉 "맛집 전문 채널/코너가 실제 방문 리뷰한 곳"만 발견 대상.

## 4. 품질 게이트 (감사 + 사용자 지시 반영)

### 4-1. 채널 게이트 (누구의 영상인가) — 신규
**맛집 리뷰를 전문으로 하는 채널 또는 맛집 리뷰 "코너"만 대상.**
- ✅ 허용: 맛집 리뷰 전문 유튜버, **종합채널이라도 맛집 리뷰 코너**(또간집, 성시경 '먹을텐데', 백종원 시리즈 등 정형화된 미식 포맷).
- ❌ 제외: SBS/KBS/MBC 등 **방송사·종합 뉴스/예능 채널**(맛집 코너가 아닌 것), 홍보/광고 채널, 식당 자체계정.
- 구현: **큐레이션 화이트리스트**(허용 채널·코너 등록) + **미등록 채널은 LLM 분류**(`channel_type: specialist | corner | broadcast_general | promo | self`). corner 판정은 영상 제목/시리즈명 패턴(또간집·먹을텐데 등) + 채널 분류 병행.

### 4-2. 콘텐츠 게이트 (어떤 영상인가) — 신규·강화
- **쇼츠 제외** — is_short=true 또는 60초 이하 배제(고품질 지향). 기존 filterPlayable 강화.
- **실제 방문 리뷰만** — `visit_type: dine_in | delivery | home | unknown`. **배달·집에서 먹는 영상 제외**(dine_in만 허용).
- **미식 리뷰성** — `content_type(review/vlog vs mukbang/comedy/promo/news)`·`tasting_review_score`. 코미디·ASMR·순수먹방 보류.

### 4-3. 매칭/대표 게이트
- **대표영상 선택**: 조회수 대신 (채널적합 × 리뷰적합도 × 신뢰도 × 인사이트충실도), 조회수는 타이브레이커. 결과를 `representative_video_id`로 저장.
- **근거 강제**: 가격/영업시간은 evidence 없으면 저장 안 함(이미 적용, 유지).
- **정직 노출**: 리뷰/데이터 결손 시 "리뷰 준비 중" 등 중립 상태. 가짜 생성 금지.

> 참고 버그: **피드·카드의 크리에이터 프로필이 대표(최적) 채널이 아닌 경우** 발생 — `representative_video_id` 도입 시 피드/카드/상세가 모두 대표 영상의 채널을 쓰도록 통일해 해결.

## 5. 프레젠테이션 (PC 우선: RestaurantInfoCard)
- 모든 블록 우아한 결손 처리(가격 없으면 점선 리더 제거, 영업시간 없으면 제보 버튼).
- 대표영상 = enrich된 영상 기본 활성(버그 수정).
- best_food_scenes "이 장면부터 보기"(구현됨) 유지·강화.
- **정직화(가짜 제거)** — PC 카드에 하드코딩 별점/mock 할인/허위 인증이 있으면 제거. (※ 대부분 모바일 `/restaurants/[id]`에 있음 — PC 우선 원칙에 따라 PC부터 점검)
- 사회적 증거: "유튜버 N명 인증 · 누적 조회 XX만", 신뢰 채널명 배지.

## 6. 확장/운영 (전국)
- **지역 설정 파일**: `{ region, kakaoRegionTokens(오매칭 방어), tourApiAreaCode, searchQueries, target }`. 광주의 "전남광주통합특별시" 함정처럼 지역별 Kakao 반환 특성 정의.
- **YouTube 쿼터**: search 100units/건, 일 10k. 전국=지역×쿼리 → **지역별 배치 + 스케줄링(cron)**로 분산.
- **비용**: 멀티모달 ~₩6~30/영상. 전국 수천 곳이면 관리 필요 — 리뷰적합 대표 1개만 멀티모달, 나머지는 텍스트/스킵.
- **멱등·증분**: place_id 기준 upsert, 채워진 필드 스킵, 실패 재시도 큐.
- **언어/구조 결정**: 현재 TourAPI/임베딩=Python(`data_pipeline`), YouTube 멀티모달=Node(`src/scripts`). 통합 방식 결정 필요(아래 오픈 이슈).

## 7. 단계별 로드맵
- **Phase 0 — 광주 49곳으로 "생성 로직" 완성·검증**: 전화 백필(Kakao) + TourAPI 편의/영업시간 보강 + 큐레이션 매칭 + 임베딩 재생성 + 대표영상·리뷰적합 게이트 + PC 카드 정직화. → 한 지역에서 완전한 상세페이지를 end-to-end로 증명.
- **Phase 1 — 지역 파라미터화**: Phase 0의 로직을 `generateDetail`/discovery로 일반화, 지역 설정 파일화. 한 지역 = 한 명령.
- **Phase 2 — PC 상세페이지 프레젠테이션 완성**: RestaurantInfoCard가 모든 블록을 정직하게 렌더.
- **Phase 3 — 전국 롤아웃**: 지역별 순차(쿼터·비용 예산), 증분.
