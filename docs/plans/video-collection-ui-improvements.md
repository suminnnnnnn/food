# 유튜브 수집 로직 · 상세 UI 개선안 (전문가 패널 종합)

_2026-07-18 · 프론트엔드/UX · 데이터/AI · 그로스 3개 관점 교차 토론 종합_

## 한 줄 결론
**"모두의맛집은 정보 앱이 아니라 '누가 보증했는가'를 파는 신뢰 큐레이션 앱"** 이라는 재정의에 세 관점이 수렴한다.
가장 큰 즉효는 **새 데이터 수집이 아니라, 이미 수집해두고 화면에 안 쓰는 데이터를 켜는 것**이다.

---

## 1. 세 관점이 모두 동의한 것 (고신뢰 · 우선 실행)

1. **이미 있는데 안 쓰는 데이터가 많다** — `mood_tags`, `best_food_scenes`(타입만 있고 추출·렌더 둘 다 없음), `subscriber_count`, `price_source`, 영상 조회수/좋아요. 신규 수집 0으로 임팩트를 낼 여지.
2. **크로스 인증("N명의 유튜버가 다녀감")** — 서로 모르는 유튜버 여러 명이 각자 추천 = 광고·우연이 아니라는, 경쟁사가 원리적으로 복제 못 하는 유일 무기. place_id로 묶기만 하면 됨.
3. **핵심 가치(한줄평)가 너무 아래(order-4)에 묻혀 있다** — 자체 리뷰 없는 서비스인데 "가야 할 이유"가 프로필·영업시간 카드 뒤로 밀림. 첫 화면으로 승격 필요.
4. **영상 하이라이트 딥링크** — `best_food_scenes` 타임스탬프로 "이 장면부터 보기". 영상 서비스의 결정적 차별점.

## 2. 프론트엔드가 발견한 준-버그 (최우선)
Review/Pick/Tip이 전부 `sortedVideos[0]`(조회수 1등 영상)에 **고정** 바인딩. 상단 플레이어만 `activeVideo`를 씀. → **캐러셀에서 다른 유튜버를 탭하면 영상은 바뀌는데 그 아래 한줄평·Pick·팁은 1등 유튜버 것 그대로.** 다중 리뷰 맛집일수록 "영상은 B, 리뷰는 A"로 읽히는 불일치. 라인 3곳(`sortedVideos[0]`→`activeVideo`) 수정으로 해결.

## 3. 데이터/AI가 제시한 수집 로직 개선
- **자막을 멀티모달에서 함께 추출 → yt-dlp/429 파이프라인 제거** (ROI 최고). Gemini가 이미 음성을 듣고 있으므로 같은 호출로 transcript 반환받으면 별도 자막 fetch 불필요 → **스로틀 병목 소멸, 파이프라인 3→2단계**.
- **근거 강제 + 게이트**: price/hours에 `evidence`(화면 원문/발화)+`ts` 필수화("인용 못 만들면 null"이 최강 환각 필터). 이미 뽑고도 안 쓰는 `match_confidence`를 저장 게이트로. 저장 직전 스키마 후처리(`price_source:none`인데 price 있으면 제거).
- **검색 `order=viewCount` 병합 + 조회수 하한** — 재시딩 목표(조회수 상위 50/하한 3만)가 현재 `order=relevance` 코드와 불일치. 반드시 반영.
- **멀티 영상 교차검증** — 여러 영상에 반복 등장하는 pick만 signature 승격, 가격은 최신 영상 우선, 가격 변동 감지.

## 4. 그로스가 제시한 신뢰/임팩트 장치
- 크리에이터 **권위 뱃지**(전문성 태그), **N명 인증**, **조회수·좋아요·최신성**(성지/웨이팅), **주문 치트시트**(먹은 것+"이건 꼭/별로").
- 공유/바이럴: **유튜버 기반 랭킹 리스트**("○○ 인정 광주 국밥 TOP5")+OG 공유카드, 유튜버 본인을 유통채널로(제로 CAC), 커버리지 게임화.

## 5. 쟁점과 판단

| 쟁점 | 대립 | 결론 |
|------|------|------|
| 데이터 더 뽑기 vs UI로 켜기 | 데이터팀은 신규 추출, FE/그로스는 기존 데이터 렌더 | **UI 활성화 먼저**(무료·즉효), 신규 추출은 재시딩에 선별 반영 |
| 정보 많이 vs 엄선 증명 | 그로스는 신뢰장치 다수, 미니멀리즘 원칙은 절제 | **적은 데이터를 '엄선됨'으로 전환**하는 3장치(크로스인증·소셜프루프·큐레이션리스트)만 |
| fps 0.2 (저비용) vs 가격정확도 | 저fps가 메뉴판 가격 프레임을 놓칠 수 있음 | 가격은 evidence+ts 강제로 보완, fps는 유지(비용 우선) |

## 우선순위 로드맵

### Tier 0 — 즉시 (기존 데이터, UI만 / 수집 변경 없음)
1. **activeVideo 바인딩 수정** (준-버그) — 라인 3곳
2. **한줄평(quote) 히어로 승격** — 영상 바로 아래
3. **mood_tags 렌더** — 이미 DB에 있음
4. **소셜프루프 노출** — 조회수·좋아요·게시일·구독자수 배지
5. **크로스 인증 배지** — "유튜버 N명 인증" (place_id 그룹)

### Tier 1 — 재시딩에 함께 반영 (지금 와이프+재시딩 예정이므로 최적 타이밍)
6. **검색 order=viewCount + 조회수 하한** — 재시딩 목표와 정합
7. **best_food_scenes 추출 + "이 장면부터 보기" 딥링크**
8. **근거 강제(evidence+ts) + match_confidence 게이트 + 스키마 후처리 검증**
9. **자막을 멀티모달 호출에서 함께 추출 → 429 파이프라인 제거**

### Tier 2 — 이후
10. 멀티 영상 교차검증(가격변동·signature 승격)
11. 웨이팅/혼잡, 댓글 감성(로컬 신뢰)
12. 유튜버 랭킹 리스트 + OG 공유카드
13. 커버리지 게임화(리텐션)

## 재시딩과의 연결 (실행 포인트)
지금 **와이프+재시딩을 앞두고 있으므로 Tier 1(6·7·8·9)을 재시딩 프롬프트/파이프라인에 함께 넣는 것이 가장 효율적**이다. 특히 9(자막 통합)는 재시딩 시 자막 스로틀을 원천 제거하고, 7·8은 프롬프트에 필드만 추가하면 되어 비용 증가 ~₩1/영상.
